# 消息渠道兼容性检查与修复

日期：2026-10-23（Asia/Shanghai）。ClawClaw 0.2.11 / DSH 0.2.1-rc.2 / dsh-im 4.20.2。

## 现象与根因

用户报告消息渠道会话不显示，随后微信、飞书均返回 `INTERNAL_UNKNOWN`。参考号 `MF-49680B00` 对应 Host 日志：

```text
session.history: Cannot read properties of undefined (reading 'signal')
```

这是两个独立问题：

1. **会话辨识度**：微信和飞书当前绑定的原会话仍在默认工作区，未归档，历史可打开。普通侧栏按时间排序，这两项会话的较早活动使其位于列表后面。旧显示适配去掉了标题的渠道前缀；原生 leading 位置在运行或等待注意时又会显示状态，而不显示渠道图标，导致渠道来源难以辨认。搜索“微信”可找到原 `Hi` 会话，确认数据没有因 UI 更新消失。
2. **实际执行失败**：固定版本 IM 的现代 Harness 适配器调用新 Gateway 时没有提供必需的 `peer`。新版 Gateway 为 `session.follow` 建立取消信号时读取 `request.peer.signal`，因缺少 Peer 在读取历史阶段失败，尚未进入模型执行。微信和飞书共享该适配器，因此同时受影响。

另在实际重启核验中发现：文件回传工具安装函数返回布尔值，直接作为 Cordis 注入回调返回值会触发 `Invalid effect`。这处初始化错误也已修复。

## 修复范围

- `channels/dsh-im/src/harness-peer.mjs`：为本机可信渠道调用提供 Host 生命周期的 Peer；同一个 Host 的渠道共享；所有 unary/stream 请求都明确带 Peer；Host 退出时释放。
- Peer 身份固定为既有的本机 owner，`interactions: none`；身份不来自聊天文本、渠道用户 ID 或 RPC payload。没有新增公开远程调用入口，没有改变机器人白名单、凭据或授权配置。
- `channel-harness-peer-patch.mjs`：在现有构建流程中适配固定版本的 `modern-harness-api.mjs` 和 `harness-command-executor.mjs`。精确匹配源码锚点，版本变化时拒绝静默构建；未直接修改 node_modules 或上游子模块。
- `src/index.mjs`：工具安装注入回调不再返回布尔值；注册仍由原上下文管理生命周期。
- `client/session-presentation.js`：普通侧栏保留“微信 · … / 飞书 · …”等渠道文字；搜索结果和会话页头保留紧凑图标；不改写正常侧栏的文本节点。清理适配时不再用旧渠道标题覆盖新标题。
- 重建随包发布的 `lib/index.js`、`lib/client.js`。

## 数据核对与保护

只读核对了现有渠道绑定与会话：

| 渠道 | 当前绑定会话 | 默认侧栏行为 |
|---|---|---|
| 飞书 | 原会话存在，已挂载默认工作区，未归档 | 显示；按原活动时间排序 |
| 微信 | 原会话存在，已挂载默认工作区，未归档 | 显示；按原活动时间排序 |
| 企业微信 | 原绑定会话存在，已归档 | 默认隐藏；未擅自取消归档 |
| QQ | 原绑定会话存在，已归档 | 默认隐藏；未擅自取消归档 |

修复过程没有主动删除会话、迁移或重建渠道绑定，没有手工修改渠道 state/config、任务定义或原运行记录。核验没有通过微信、飞书发送测试消息，也没有主动重放此前失败消息。用户后续主动发送的消息可以正常沿用原会话。

## 回归证据

1. 渠道 Node 测试：31 项通过，包含共享 Peer、覆盖外来 Peer 字段、保留取消信号、释放生命周期、缺少能力时拒绝以及两处构建锚点检查；另覆盖 Cordis 工具安装回调不返回非法 effect。
2. 展示组件测试：3 项通过，验证运行状态占用 leading 位时仍保留渠道名、普通标题更新不被旧值覆盖、搜索/页头图标和卸载还原。
3. 真实临时 Profile 集成：新增 `verify-channel-harness.mjs` 接入默认 `verify:profile` 门禁。使用实际 Gateway 和 HarnessClient、真实临时工作区与会话，离线模型替代付费外部模型。
   - 先确认未修补的固定版本适配器在历史读取时复现原始 `signal` 错误。
   - 飞书、微信两种 RPC 来源分别验证创建会话、重命名、初次历史读取、提问、接收完整回复、再次历史分页及会话列表。
   - 每种来源仅执行一次目标模型请求；使用明确标题避免把后台自动命名请求误计为重复执行。
   - fixture 强制检查临时 Profile 路径，不使用真实数据目录或真实渠道账号。
4. 类型检查、构建、完整仓库门禁及实际重启结果见最终验证记录。

## 验证边界

共享的现代 Harness 适配器覆盖其他 IM 渠道，但本次针对用户报告的飞书和微信执行真实临时 Profile 流程；其他第三方渠道未逐个发送在线消息。文件回传的初始化回归覆盖了工具注册，不代表已向真实微信/飞书发送附件。生产环境只查看连接状态和用户主动消息的执行结果。
