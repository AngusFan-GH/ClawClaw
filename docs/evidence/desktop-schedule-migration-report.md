# Desktop 自动化迁移报告

日期：2026-10-23。目标：DSH 0.2.1-rc.2 官方 Schedule 核心 + Desktop 兼容层。ClawClaw 产品版本保持 0.2.11。

状态：实现、自动化门禁、真实数据迁移、正常重启及窗口核验全部完成。实现提交：`05e95adba6`。

## 实现与影响范围

- `desktop-schedule.ts` 实例化官方 `ScheduleService`，使用其原有计时器、发生时点计算、会话消息投递和投递回执逻辑。上游子模块保持不变。
- Desktop 保留现有自动化表单、五个 `cron_task_*` 管理工具、立即运行、启停、取消、60 分钟超时、通知及真实执行结果记录。
- 生产环境的 `CronTaskController` 注入官方调度 driver，原定时器不再启动，没有并行的旧调度器或失败后回退。
- 独立的官方插件入口、原生投递管理 UI 和 `schedule_*` 工具保持关闭；兼容层是唯一管理入口。官方服务写接口被拒绝，避免绕过执行账本创建另一份任务目录；其只读目录仍用于核验。
- 旧配置命名空间仅作为首次导入源，退出自动生成的设置表单。后续读写由独立的持久化注册表负责，避免设置写入重载执行中的插件。
- 自动化执行期间禁止再次操作调度管理工具；额外的工具 guard 覆盖后续注册的官方 Schedule 工具。

## 任务、会话与历史保留

每个 Profile 根据目录生成独立存储名称：

- `desktop_schedule_registry_<scope>`：原始快照、当前任务、已删除任务归档及执行认领信息。
- `desktop_schedule_core_<scope>`：官方 Schedule schema 的任务、绑定会话和投递回执。

两者经 storage-domain 使用标准 JSON 后端持久化，不覆盖原生全局 `schedule` 存储或其他 Profile。

1. 首次导入先写入受限权限的 `migration-backups/desktop-schedule-v1-<sha256>.json` 并同步落盘。
2. 校验所有规则后，在一个持久全局记录中保存原始任务快照、任务集合和迁移标记；核心表可按该记录幂等重建。
3. 保留已有任务 ID、名称、提示词、时区、原有会话 ID、工作区关联和全部现存历史记录。不将执行成功/失败伪装为官方投递回执。
4. 不再截断兼容层历史到 20 条。迁移前快照只读保留；删除任务时另存包含完整运行历史的归档，并保留会话。归档数据通过现有 API 的 `archivedJobs` 返回，当前 UI 未增加独立的删除任务归档页。
5. 没有关联会话的新任务先持久化预留会话 ID，再创建空会话；重启不重新分配 ID。不对缺失的旧会话或工作区静默重建替代品。
6. 归档会话并选择停止活动时，会取消相关执行并持久停用计划，重启不会将其重新启用。须先取消会话归档才能重新启用对应计划。

首次迁移从 Loader 实际配置读取初始值，避免异步启动期间设置表单尚不可读而误导入空集合。持久化解码器不为可选运行结果生成空对象。

## 不补跑和防重复策略

- 启动时将错过的计划推进至严格未来，增加“跳过”记录；已中断的认领记录标记失败，不自动重放。
- 启动前已经入队的 Schedule 消息会在模型入口被拦截。
- 运行期间若官方核心选择的最近错过时点与已提交目标不一致，或投递恢复延迟超过 60 秒，同样记录跳过，不调用模型。60 秒是正常计时与会话恢复的容差，不是补跑窗口配置。
- 每次执行先持久化发生时点和消息 ID，再允许模型调用。认领写入失败时拒绝执行。
- 已认领时点、同任务重叠执行、跨会话错误绑定和重复消息会被拒绝；允许集合仅覆盖当前 Agent 的当前 turn。
- 拦截旧消息时也拒绝由其他监听器附加的时钟/模型通知所形成的空模型请求。
- Profile 排他锁和应用单实例约束防止新版本的多个 Host 同时取得调度权；损坏的锁证据拒绝接管，死进程锁在排他恢复区中回收。

这是一种保守的至多一次执行准入策略，不是外部副作用的事务保证。认领落盘后、模型调用前崩溃，可能导致一次工作未执行且不再补跑；这是“不自动重试、不重复副作用”的取舍。人工再次点击“立即运行”、丢弃认领存储或外部服务自身重试不在自动去重保证内。

## 实际数据迁移审计

实际任务迁移在应用正常退出、备份后执行。备份覆盖数据目录与应用状态目录，共 17,030 个文件、1,637,309,796 字节，附 SHA-256 清单；外部工作区业务文件未复制，也未修改。

实际结果：

- 原任务与官方核心均为 2 项，没有重复任务；任务 ID、规则、时区、启用状态及原会话关联不变。
- 原有 40 条运行记录全部保留。每项任务各增加 1 条离线错过的跳过记录，现共 42 条；没有为验证手动运行真实任务。
- 全部 492 个原有会话日志的 SHA-256 与备份相同，当前日志文件总数仍为 492。
- 原 Profile 的 cordis.patch.yml 也与备份字节相同，旧配置没有被清空或改写。
- 实际窗口显示两项任务保持启用，2026-10-23 上海时区的下一次执行时间分别为 15:22、21:00；详情可以查看原历史记录。
- 正常重启后重复审计，任务映射、历史条数、源快照哈希及会话日志校验结果均相同。没有自动认领或补跑任务。

受限权限的本地完整报告和 `migration-audit.json` 记录备份路径、任务映射、源快照校验和及审计时刻；不把提示词、凭据或会话正文写入仓库报告。

可重复执行的只读审计命令：

```sh
node dsh-plugin-desktop/scripts/verify-schedule-migration-data.mjs <data-dir> <backup-dir> desktop
```

审计比较迁移前备份与迁移后注册表，检查规则、启用状态、任务和会话身份、原运行记录，以及备份中所有会话日志的 SHA-256。它不触发任务，也不修改数据。

## 回退及维护

- 保留迁移前完整备份及源码提交。迁移后的状态和原任务配置同时保留，不能据此同时启动旧、新两套程序。
- 回退前退出全部 ClawClaw 进程，并另存迁移后的数据。若切换后没有新增会话内容或工具副作用，可评估恢复完整旧备份；否则必须保留新增会话并按执行认领记录对账、只安排未来时点，不能用旧快照覆盖掉新数据。
- 不存在回滚外部工具副作用的能力，也不应通过删除认领记录来强制重试。
- 原生 Schedule 的六类规则尚未全部暴露到兼容表单；本次支持并保留原有五字段 Cron 和一次性计划。对不支持的 Cron 方言或观察到的未来时点差异拒绝迁移，不静默转换。校验比较未来 8 个时点，不宣称穷尽所有未来时区数据库变化。
- 历史记录当前不自动裁剪，长期运行后存储会增长；未来若引入保留策略，应提供明确归档和导出，不能重新截断旧数据。
- `.recovery` 所有权恢复文件若因进程崩溃遗留，会保守拒绝启动；须先确认所有相关 Host 已退出并保留现场后人工处理，不可在活跃 Host 运行时删除锁。
