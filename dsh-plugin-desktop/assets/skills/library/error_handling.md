# error handling

When to read: an action returns `{"error": ...}`. Read this file and follow the rules. Do not read for normal calls.

## Error-code actions

On `{"error": ...}`, extract `code=<error-code>` and act by the rules below. Safe `msg` is used only to add parameter / state / restricted-object context. Scripts and outer wrappers must not invent next steps; when multiple layers wrap a code, the innermost backend business code wins and only one rule fires. Error codes are for model decisions; convert to natural language when shown to the user, never expose the internal code.

1. **`11607` / `INVALID_PARAMS`, msg contains 「不支持语音解析」 — format not supported**: tell the user this format has no transcript parsing, stating the current format and the server's supported-format list; if needed, suggest re-uploading in a supported audio format. No retry.
2. **`11007`, `11607`, `56040`, `400` / `HTTP_400`, `413` / `HTTP_413`, `422` / `HTTP_422`, `INVALID_PARAMS`; or no code but local param-validation failure — invalid params**: correct the failing param, taking the correct format from the current module `entry.md` / script `--help`; ask the user if uncertain. Retry max 1. Exception (library doc direct edit): `11607` on an `update` action is not a param error — target inside a `TableCell`: switch to whole-table replacement per `doc/tasks/table_edit.md` §2; any other text block: direct-edit `update` is dead end-to-end, switch to `insert_after` + `delete` pair per `doc/content_contract.md` §4. No verbatim retry.
3. **`E_CONSENT_REQUIRED` — host-side authorization pending**: tell the user to complete authorization in the ClawClaw client, then retry; do NOT retry on your own, do NOT bypass. Max 1 retry after the user confirms they have authorized.
4. **`E_ENDPOINT_UNTRUSTED` — host IPC endpoint cannot prove its identity**: stop immediately and say access was halted for safety; retry is forbidden, downgrading to any other channel is forbidden. No retry.
5. **`E_METHOD_UNKNOWN`, `E_METHOD_KIND_MISMATCH` — host capability missing**: tell the user to upgrade the ClawClaw client, naming the missing channel capability; do NOT hard-try with tweaked params. No retry.
6. **`AUTH_REQUIRED` (host channel not connected or not opened) — not logged in or channel not authorized**: tell the user to complete login/authorization in the current runtime, then retry; do NOT report as insufficient library permission, do NOT search other credentials. Max 1 retry.
7. **`12100`, `12607`, `56030`, `401` / `HTTP_401`, `403` / `HTTP_403` (except when the permission module says the capability is disabled) — insufficient permission**: report directly to the user, stating the current role (real role if known, else "not logged in or unknown role"), the missing permission, and the restricted `nodeId` / `spaceId`. No retry.
8. **`56161` — re-import permission (dedicated, not generic 403)**: this is a re-import (`import_html.py` carries `--node-block-id`) and the user has only editor role. Tell the user re-import requires admin; guide to AI editing — `page/edit-flow.md` via `page/entry.md` §Routing; editor role suffices for transactional incremental edit. Copy in `page/import-flow.md` §7.1. No re-import retry; switch to AI editing.
9. **`11510`, `404` / `HTTP_404`, `410` / `HTTP_410` — resource not found**: if the `nodeId` exists, re-resolve via `space.workspace.node-info` once; else re-resolve from a valid link (the old path is marked invalid). No repeat old path.
10. **`11112`, `19901`, `56039`, `409` / `HTTP_409`, `423` / `HTTP_423` — state / version conflict**: re-read the latest state (the module's latest-read method) and rebuild per `mutation.md`; previous confirmations and old transactions are void. No reuse.
11. **`18406`, `56029`, `501` / `HTTP_501`, `CAPABILITY_DISABLED`; permission-module `403` / `HTTP_403` from the apply/invite switch — capability not enabled**: state explicitly which capability is disabled and offer the available alternative. No retry.
12. **`619610` / `11511` (content safety), `56031` (personal → enterprise drive), `56032` (enterprise → personal drive), `56033` (cross-enterprise), `56034` (space owner only), `56035`–`56037` (space-restricted ops), `56041` (security disposition) — protected resource**: state the protection rule directly, naming which bracket rule and which restricted object. No retry.
13. **`429` / `HTTP_429`, `50001` — rate limit**: stop the current consecutive calls and suggest pausing. No immediate retry. `50001` is the database-module business code — **30 QPS per table** (`database/entry.md` §Rate limit) and, for page SDK calls, **20 QPS per page** (`page/database-sdk-contract.md` §1.1). Same action as HTTP 429; do **not** treat it as `50000` transient.
14. **`50000`, `56038`, `500` / `HTTP_500`, `502` / `HTTP_502`, `503` / `HTTP_503`, `504` / `HTTP_504`, `NETWORK_ERROR`, `TEMPORARY_ERROR`, `INVALID_RESPONSE`, `UNKNOWN` — transient failure**: the mutation may have already succeeded — query state first via the module's read-only status query; only re-submit if status shows it did not land. No blind re-submit.
15. **`524` / `HTTP_524` — volume-triggered timeout**: the batch may have partially landed — read back what landed via the module's read-only status query, then resume in smaller batches per the module's volume quota (library doc: `doc/server_pitfalls.md` §3). Never re-submit the same oversized payload; splitting the payload, not retrying, is the fix.
16. **`E_AUTH_REQUIRED` — Taihu browser authorization needed**: the script already tried to open the system browser. Tell the user to finish authorization in the window that just opened; after they confirm, retry the **same** command once. stdout JSON has `auth_url` (also duplicated as `auth_url=` inside `error`) as a fallback only if no window appeared — then forward that URL. Do not auto-retry, do not start a new authorization yourself.
17. **`E_NOT_CLAWCLAW`, `E_TAIHU_UNAVAILABLE`, `E_AUTH_TIMEOUT`, `E_AUTH_FAILED` — env/auth hard failure**: not transient. Tell the user to fix the runtime or complete authorization; do not auto-retry; do not point them at a specific client. `E_NOT_CLAWCLAW` only: max 1 retry after the user confirms the host is up. `E_TAIHU_UNAVAILABLE`: no retry. `E_AUTH_FAILED` from a rejected `TAI_PAT_TOKEN`: tell the user the token was rejected; they can replace it, or unset the env var and retry to use browser OAuth.
18. **`56150` — database write row quota**: CSV import or adding records would exceed the table's 10,000-row cap (`database/params-reference.md` §Limits). Tell the user the table cannot take more rows; split the dataset or import fewer rows. Never retry the same payload. No retry.
19. **`56152` — database column quota**: create / add-field / CSV import would exceed the 50-column cap (`database/params-reference.md` §Limits). Tell the user to drop columns before retrying. Never retry the same schema. No retry.
20. **`56153` — database row too large**: a written record exceeded the 1 MB per-row cap (`database/params-reference.md` §Limits). Tell the user to shrink that row's cell values (long text / attachments). Never retry the same row. No retry.

Backend codes not listed above, and no-code errors that are not clearly local param validation, are handled as transient failure. Safe `msg` may be quoted to describe the symptom, but never overrides the retry rules above. Query state first, then decide whether user intervention is needed.
