# 会后总结与行动承接

## 依据与提取

用户主动要求总结或提取行动项时，读取其提供或授权获取的会议记录。计划结束不等于会议实际发生或纪要已生成；无记录时不根据标题生成结论。记录不完整时标明覆盖范围，不重复发送系统纪要卡。

1. 核实会议/实例关联、资料来源、版本和权限；手动提供的记录可直接总结，无须等待正式纪要。
2. 提炼决定、开放问题和候选行动项，区分已确认事实、讨论提议与助手建议。每项保留动作、来源、明确的负责人和期限；未知项不猜。
3. 对照已有处理记录；忽略、拒绝或已承接事项不反复询问。从记录提取的候选行动项按 SKILL「不确定时提问」让请求用户选择（优先 `send_card`）；用户已明确要求创建具体待办时沿用授权，不再确认一次。

## 创建或查询待办

通过 ToolSearch 按需发现 builtin-teams-todo 工具，同一 Agent 继续执行，不强制读取待办 Skill。Plugin 不可用时保留候选并说明未创建；只总结材料时不加载 Todo 工具。

- 项目来自宿主有效绑定，不能用 calendar_id/channel_id 代替。人员已有明确可信用户 ID 时直接使用；确需消歧时使用已授权 IM 的 list_channel_members，不调用 project_members。群成员身份不等于项目指派权限，以待办服务校验为准。
- 保留已有授权和会议来源，只补工具必需信息。有已有待办标识、处理记录或疑似重复时定向核实，不重复创建，不自动合并相似事项。
- 按实际工具定义读写，配置不明时按需查询 todo_config。来源关联只用工具支持字段或宿主映射，不能因交接了来源就声称已保存。
- 创建不授权催办或派发；mention_assistant 默认关闭，只有用户授权对应副作用时使用。Plugin 不含任意助理委派工具，不承诺派发或执行完成。
- 逐项返回实际 ID、状态、来源关联及失败原因，交宿主保存处理记录。写入状态不明时先核实，不能盲目重建。

## 持续进展

待办服务是状态事实源。没有更新不等于未开始，初稿产出不等于完成。只读进展请求不顺手修改状态或催办。

纪要修订可调整未确认候选；对已建事项给出变化建议，不自动修改负责人、期限或删除。会议取消不自动取消历史待办。向目标项目写入内容前检查披露范围，不能扩散私密会议材料。
