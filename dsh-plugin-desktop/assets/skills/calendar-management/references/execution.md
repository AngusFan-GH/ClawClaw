# 特殊情况处理

## 参与范围与目标

- 点名只邀请点名人员；“全频道”使用有权限获取的当前成员快照，不随日后成员变化回写日程。“相关同学”范围不明确时确认，不猜成员。请求人需要参会时核实其实际在名单中。
- 人员预览可能截断，不能用预览名单覆盖完整邀请范围。人员读取取决于宿主授权，不能通过换入口或换身份绕过。
- 用户明确要求团队日历而上下文回落个人时，先解决归属差异，不静默创建。日历身份与 Todo 项目身份不能互换。
- 主题检索若无专用参数，在有界时间范围查询后筛选，说明覆盖范围；遵循分页，不能把一页结果当作全部。

## 问答与确认

提问方式以 SKILL「不确定时提问」为准：先确认当前会话有 `send_card`，有则优先用它；没有再回落 `AskUserQuestion` 或自然语言。只使用实际问答工具的能力，不自建卡片 Schema，不编 `template_id`。保留已知信息并合并必要问题。未回复、默认选中或关闭不算同意；由宿主校验回答用户与请求关系。

候选选择与执行授权分开判断；有既有执行授权且服务端不另要求确认时继续执行。确认须覆盖最终方案及影响；方案变化后重新获取适用凭证。保留冲突时间必须符合工具能力及确认要求，不替用户忽略冲突。

## 失败与恢复

网络失败不证明未写入；按工具契约复用幂等标识核实或重试，不换新标识强行创建。有限重试仍无法确定时停止自动写入并说明状态待核实。版本冲突先读取最新详情，不覆盖其他人的变化。时间候选失效重查候选，确认超时按工具要求更新凭证。

部分成功依据回执和最新状态说明实际范围，不直接重放已生效步骤。已建日程的资料、预订或通知失败，不通过重建日程修复；仅在工具支持的恢复流程中继续。

问答提交不等于写入成功，写入成功不等于通知已送达。固定投递由宿主恢复，不自行补发相同通知或猜测 @对象。
