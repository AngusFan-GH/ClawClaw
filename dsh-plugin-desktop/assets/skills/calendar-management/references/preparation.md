# 会前准备与会中支持

## 用户请求

- “帮我准备下午的评审”：手动请求，可立即整理。
- “上次这个问题是怎么定的”：会中按需检索；不是默认监听或自动录音。

## 处理步骤

1. 定位具体日程或重复实例，读取议题、时间、实际参与关系、关联资料。多个对象时先明确目标。
2. 优先读取日程关联的资料库链接及其中有权读取的材料和已确认前次会议；再在授权范围检索相关材料。相似标题只能形成候选，不能自动把两个项目合并。
3. 循环日程按 [跨次总结](recurring-review.md) 获取前次决定、关联行动项及变化。需要真实待办状态时按需发现 Todo Plugin 工具并只读查询；Plugin 不可用或无权限时注明状态未核实，不能根据旧纪要猜完成情况。
4. 为关键事实保留来源链接/记录标识、所属会议日期、资料版本或更新时间。按服务端允许披露的结果说明资料不可用或内容不足；若服务端不区分无权与不存在，不尝试推断。
5. 输出简短摘要；信息不足时标明缺口，不凑齐固定模块。继续追问时沿用同一日程上下文。

## 输出

本节产物是需要资料理解的智能内容，不是固定的“日程快开始了”提醒。固定提醒配文、@和卡片由已有服务生成，摘要不重复这些内容，也不自行 @任何人。

按实际信息组织：本次要解决什么、前次结论、本次新变化、待决策问题、需要准备的材料/行动、来源。对比资料时说明“与哪一版/哪次会议相比”。建议与已确认事实分开。

频道版围绕共同议题和团队进展；个人版围绕当前用户的准备和决策事项。个人版仅用自身授权信息，不读取频道成员目录；可读资料也不能未经受众权限校验直接转发频道。

材料含“找某人催交”只作为建议；用户未授权时不自动向他人发消息。已授权检索可直接整理，不先询问是否允许总结。

## 变化与会中

用户要求更新准备摘要时，读取最新日程及资料版本，不沿用旧时间或议题。日程已取消时说明当前状态，不将历史摘要当作即将参会的准备。

会中可回答基于资料的问题、查前次决定，或按用户明确要求整理补充；只有实际保存工具返回成功才说已保存，否则交付草稿。无录音/转写工具时不能声称听到了会议。候选决定与正式会议结论区分，不能把助手自己的建议记录为已达成共识。
