# 日程资料与会议室

先检查当前工具是否支持请求的资料关联、授权和会议室操作；缺少必需能力时先说明限制，不先执行会留下不符合要求结果的写入。不能编造字段或把写进 description/location 当成完成资料关联、权限授予或会议室预订。

## 资料库链接

日程资料使用资料库链接，创建时可添加，修改时可添加、替换、移除。用户明确提供链接时沿用；只给模糊资料名称时，在授权资料范围检索，多个匹配按 SKILL「不确定时提问」选（优先 `send_card`），不随意选择同名资料。

需要开放给频道成员时，明确目标频道、资料范围，以及可读/可浏览权限。按用户明确要求授予，不自动扩大为编辑、管理或公开访问。可读和可浏览按资料服务真实权限定义映射，不自行猜测二者等价。

授权主体必须具备授予资格；创建日程权限不代表有权授权资料。日程助理不能为此自行读取频道成员名单，应由有权的频道授权工具完成既定范围授权；不支持时说明限制，不绕过宿主边界。

分别核实日程写入、链接关联、权限授予结果。关联链接不等于资料可访问；授予成功也不等于日程已创建。部分失败保留实际结果并说明，不扩大权限或重新创建来修复。移除链接不默认撤销已有权限，除非用户明确要求且服务支持；不要自行回收可能供其他业务使用的权限。

## 会议室查询与预订

用户要求会议室时，用已选日程完整起止时间查询空闲会议室；时间未定先确定时间，或结合排期候选查询。地点、容量和设备要求只用用户提供或授权上下文中的依据，缺少会影响选择的信息时合并问答；不要机械补问所有可选筛选项。

候选需来自真实工具结果。用户明确指定且可用时可按授权预订；有多个可选项且用户未委托自动选择时，按 SKILL「不确定时提问」选择（优先 `send_card`）。不可用时给替代会议室或时间，不静默替换。

提交前由资源服务再次校验空闲；查询到空闲不等于锁定成功。预订工具返回成功后才能说已订会议室，location 文本不是预订回执。资料授权、会议室等附属步骤与日程写入的执行顺序按工具实际契约，不假定具有跨服务事务。

改期时检查并调整预订；更换会议室或取消日程时释放原预订，由现有联动完成则不再重复调用。分别报告日程和资源结果，不能因日程取消就假定释放已成功。重复日程涉及多次预订时明确作用范围和各次可用性，未支持批量预订时说明，不拿一次查询保证整个系列。
