# 仪表盘规划文本格式

> 本文档定义两类规划文本：
> - `wb_smartsheet.create_dashboard_from_plan` 的**整盘规划**（`dashboard_plan`）
> - `wb_smartsheet.add_dashboard_component` / `wb_smartsheet.update_dashboard_component` 的**单组件规划**
>
> ⚠️ 规划文本**只作参数传入，严禁展示给用户**（详见文末）。

## 零、前置：标识必须现取

规划文本里的 `tableId` / `fieldId` / `viewId` / `optionId` 全部是**真实标识**，必须来自实际调用的返回：

| 需要什么 | 从哪来 |
|---|---|
| `tableId` | `wb_smartsheet.list_tables` 返回的 `sheet_id` |
| `fieldId` | `wb_smartsheet.list_fields` 返回的 `field_id` |
| `viewId` | `wb_smartsheet.list_views` 返回的 `view_id` |
| `optionId` | `wb_smartsheet.list_fields` 返回的列属性里的选项 ID |
| `component_id` | `wb_smartsheet.get_dashboard` 返回的组件索引 |

**禁止编造，禁止使用 `table_plan` 里的 `F1` / `T1` / `V1` 占位符**——那些编号建表后即失效，写进仪表盘规划必然编译失败。

建盘前表必须已建好**且已填入记录**：空表能建出组件，但每张图都是空的、每个数字都是 0。

## 一、整盘规划（`dashboard_plan`）

一次调用只建**一个**仪表盘。文本含四个段落，顺序如下（下面是 `dashboard_plan` 的原文，缩进仅为本文档排版）：

    ## 仪表盘1：项目运营看板

    ### 全局风格
    - themeIndex: 1
    - colorType: 0

    ### 组件列表
    1. 项目状态分布 | T1 | PIE
       - 数据源：tvmijz
       - 分类轴：fyz3Ih
       - 数值轴：COUNT
       - 主题色：0

    2. 进行中项目数 | T3
       - 数据源：tvmijz
       - 数值轴：COUNT
       - 筛选：fyz3Ih = oQKhzE
       - 主题色：1

    ### positions
    ```json
    [[0,0,6,4],[6,0,6,4]]
    ```

| 段落 | 必填 | 规则 |
|---|---|---|
| `## 仪表盘1：{名称}` | ✅ | 标题不能为空；**整段文本里恰好一个仪表盘标题**，出现多个会被拒绝 |
| `### 全局风格` | ❌ | `- themeIndex: {数字}`、`- colorType: {数字}`；省略则用默认风格 |
| `### 组件列表` | ✅ | 至少一个组件；每个组件以 `{序号}. ` 开头，格式见第二节；组件之间空一行 |
| `### positions` | ❌ | 紧跟一个 json 代码块（三反引号 + `json`），内容是 `[[offsetX, offsetY, width, height], ...]`，**按组件列表的顺序一一对应**；省略或条数不足时，缺的组件按 6×4 自动两列排布 |

## 二、组件规划

### 2.1 组件头

整盘规划里带序号：

    {序号}. {组件名称} | T{类型} | {子类型（可选）}

`add_dashboard_component` / `update_dashboard_component` 传单组件规划时**不带序号**：

    {组件名称} | T{类型} | {子类型（可选）}

### 2.2 组件命名

**用业务语言命名**，不要用技术术语或序号：

- ✅ `项目状态分布`、`月度销售额趋势`、`高优先级任务数`
- ❌ `饼图1`、`柱状图`、`组件A`

### 2.3 组件类型

| 简写 | 含义 | 子类型 / 说明 |
|---|---|---|
| T1 | 图表 | `COLUMN`（柱状图）/ `STACKED_COLUMN`（堆积柱）/ `LINE`（折线）/ `PIE`（饼图）/ `DONUT`（环形）/ `AREA`（面积） |
| T2 | 表格 | 展示明细数据，⚠️ 必须指定分组字段 |
| T3 | 数字卡 | 关键指标 KPI |
| T4 | 文本 | 标题或说明文字 |
| T5 | 词云 | ⚠️ 必须指定文本字段 |

### 2.4 格式硬约束（严格执行）

组件头之后，**每个属性独占一行**，以 `   - ` 开头（3 个空格 + 短横线 + 空格）。

**严禁单行格式**：

    待入职员工数 | T3 | 数据源：tI07GZ | 数值轴：COUNT | 主题色：3

这种写法会让解析器识别不到数据源等属性，创建失败。

**必须多行缩进**：

    待入职员工数 | T3
       - 数据源：tI07GZ
       - 数值轴：COUNT
       - 主题色：3

### 2.5 数值轴写法硬性规则

- `COUNT` 表示统计记录数，必须**单独写成 `COUNT`**，不带字段 ID，也不带竖线。
  - ✅ `数值轴：COUNT`
  - ❌ `数值轴：f8zSUZ | COUNT`
  - ❌ `数值轴：任务状态 | COUNT`
- 字段聚合只支持 `fieldId | SUM/AVG/MAX/MIN`，**不支持 `fieldId | COUNT`**。
- 要统计某个状态 / 视图下的记录数，用 `视图：viewId` 或合法筛选限定数据范围，再写 `数值轴：COUNT`。
- 「完成率」只有在存在百分比 / 进度 / 数字字段时才能用 `fieldId | AVG`；若只是统计已完成记录数，就命名为「已完成任务数」，不要叫「完成率」。

## 三、各类组件的属性

### 3.1 图表组件（T1）

```
组件名称 | T1 | COLUMN
   - 数据源：tableId（必填）
   - 视图：viewId（有合适视图时写此行；无视图则省略此行，表示全表）
   - 分类轴：fieldId（必填）
   - 数值轴：COUNT（统计记录数，必须单独写 COUNT）或 fieldId | SUM/AVG/MAX/MIN
            ⚠️ 无拆分轴时可以多个（逗号分隔，如 field1|SUM, field2|AVG）；有拆分轴时仅支持单个
   - 拆分轴：fieldId（可选，不需要则省略此行）
   - 筛选：fieldId 操作符 值（可选，仅在无视图行即全表时可写；有视图行时不写此行）
   - 主题色：0-13（可选）
   - 横轴标题：分类轴的业务含义（如「项目状态」「月份」）⚠️ 仅 COLUMN/STACKED_COLUMN/LINE/AREA 需要，PIE/DONUT 不写此行
   - 纵轴标题：数值轴的业务含义（如「销售额」「任务数量」）⚠️ 同上
```

筛选操作符：`=` `!=` `>` `>=` `<` `<=`
合法值类型：`optionId`（选项 ID，`o` 开头）/ `true`|`false` / 数字字面量
⚠️ **严禁用日期字段或日期值作筛选条件**（如 `fieldId >= 2024-05-01`），仪表盘编译器不支持日期类型筛选值，必然失败。

主题色取值：

| 值 | 含义 |
|---|---|
| 0 | 使用字段自带颜色（**仅饼图 / 环形图**可设置） |
| 1 | 彩虹混色系 |
| 2 | 深色调混合系 |
| 3 | 浅粉紫 + 蓝系 |
| 4 | 多色低饱和系 |
| 5 | 蓝绿黄浅系 |
| 6–13 | 单色系渐变：6 纯蓝 / 7 蓝紫 / 8 纯绿 / 9 纯青 / 10 橙粉 / 11 黄白 / 12 棕米 / 13 黑白灰 |

### 3.2 表格组件（T2）

```
组件名称 | T2
   - 数据源：tableId（必填）
   - 视图：viewId（有合适视图时写此行；无视图则省略此行，表示全表）
   - 分组字段：fieldId（⚠️ 必填）
   - 主题色：0-9（可选）
   - 筛选：fieldId 操作符 值（可选，仅在无视图行即全表时可写）
```

操作符：`=` `!=` `>` `>=` `<` `<=` `CONTAINS` `DOES_NOT_CONTAIN` `IS_EMPTY` `IS_NOT_EMPTY`（后两个无需写值）
⚠️ 同样**严禁**日期字段 / 日期值作筛选条件。

### 3.3 数字卡组件（T3）

```
组件名称 | T3
   - 数据源：tableId（必填）
   - 视图：viewId（有合适视图时写此行；无视图则省略此行，表示全表）
   - 数值轴：COUNT 或 fieldId | SUM/AVG/MAX/MIN ⚠️ 仅支持单个
   - 主题色：0-9（可选）
   - 筛选：fieldId 操作符 值（可选，仅在无视图行即全表时可写）
```

### 3.4 文本组件（T4）

```
组件名称 | T4
   - 内容：标题或说明文字
   - 背景色：颜色代码，如 #1450B8
   - 字体颜色：颜色代码，如 #FFFFFF（可选，不指定时按背景色自动计算）
```

### 3.5 词云组件（T5）

```
组件名称 | T5
   - 数据源：tableId（必填）
   - 视图：viewId（可选）
   - 文本字段：fieldId（⚠️ 必填）
   - 主题色：0-9（可选）
```

### 3.6 T2 / T3 / T5 的主题色

`0` 深蓝 / `1` 浅蓝 / `2` 绿 / `3` 红 / `4` 橙 / `5` 黄 / `6` 紫 / `7` 粉 / `8` 黑 / `9` 灰。按数据含义选色，如红色表示风险、绿色表示完成。

## 四、位置布局

`positions` 里每一项是 `[offsetX, offsetY, width, height]`，网格宽度共 12 列：

| 约束 | 取值 |
|---|---|
| `width` | 2 – 12 |
| `height` | ≥ 2 |
| `offsetX + width` | ≤ 12 |
| `offsetX` / `offsetY` | ≥ 0 |
| 组件之间 | **不能重叠** |

`wb_smartsheet.add_dashboard_component` 需要单独给出该组件的 `[offsetX, offsetY, width, height]`，且不能与仪表盘上已有组件重叠——先 `wb_smartsheet.get_dashboard` 看清现有组件的位置，再挑空位。

`wb_smartsheet.update_dashboard_component` **不改位置**：传入完整的组件规划整体替换配置，原位置保持不变。它不支持只改某一个属性，所以要先 `wb_smartsheet.get_dashboard_component` 读出当前配置，再写一份完整规划。

## 五、数据选择原则

- **数值轴 / 度量**：**仅限** `number`、`currency`、`percentage`、`progress` 字段，可用 SUM/AVG/MAX/MIN
- **分类轴 / 分组字段**：`single_select`、`multi_select` 字段
- **时间轴**：`date` 字段
- **禁止**：`user`（人员）字段不能作任何轴
- ⚠️ **文本字段不能做数值统计**：表里没有数字类字段时，数字卡只能用 `COUNT` 统计记录数
- ⚠️ **`COUNT` 只统计记录数**：必须写 `COUNT`，不能写 `fieldId | COUNT`；要限定范围就用视图或筛选
- ⚠️ **多数值轴规则**：图表**无**拆分轴时可给多个数值轴（逗号分隔）用于对比多个指标；**有**拆分轴时仅支持单个；数字卡仅支持单个
- 不要用「以日期为筛选条件的视图」作数据源
- ⚠️ **严禁在筛选里使用日期字段或日期值**。要按日期范围取数，先用 `wb_smartsheet.add_view` 建一个带日期筛选的视图，再在组件里用「视图」行引用它
- **优先直接引用已有 `viewId` 作为数据范围**；确实要基于整张表取数时，才省略「视图」这一行

## 六、规划文本展示约束

⚠️ **仪表盘规划文本严禁向用户展示。** 组件类型、`T1`/`T2`/`T3` 标记、数据源 ID、字段 ID、筛选条件、主题色编号、`positions` 数组等，只能作为工具参数传入，不得出现在回复正文里。用户可见的只应是简短过渡文案（如「正在创建仪表盘」）与最终结果说明。

## 七、无法满足需求时

当需求无法满足（缺表结构信息、字段类型不支持统计、无合适视图等），**不要硬凑规划**，改为输出：

```
## 无法满足您的需求

### 原因
简要说明无法满足的具体原因

### 建议
- 建议1：如何调整需求使其可实现
- 建议2：替代方案
```

常见无法满足的场景：

- 表结构信息缺失（拿不到 `tableId` / `fieldId` / `viewId`）
- 需要的字段类型不在支持列表中
- 字段类型与统计需求不匹配（如对文本字段做 SUM / AVG）
- 表里没有数字类字段却要求数值统计组件
