# Product and design review

Frame the user, situation, job to be done, current workaround, and measurable outcome. Distinguish direct evidence from stakeholder assumptions.

Trace the primary workflow from entry to completion, including empty, loading, error, permission, cancellation, and recovery states. Check that labels, hierarchy, controls, feedback, focus order, and responsive behavior support the user's next decision.

For each proposed change, state user value, supporting evidence, scope, dependencies, implementation cost, operational cost, risk, reversibility, and acceptance signal.

Prioritize a coherent minimum outcome rather than disconnected features. Preserve established design-system conventions unless the request requires changing them.

Deliver the recommended flow, prioritized issues, open assumptions, and a validation plan. Do not present an untested preference as user research.
