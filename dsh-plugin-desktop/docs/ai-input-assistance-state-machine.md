# AI 输入辅助：状态与验收

## 功能边界

| 功能 | 请求条件 | 显示条件 | 采纳 | 取消/失效 |
| --- | --- | --- | --- | --- |
| 下一步建议 | 当前已有完成的对话上下文；Host 已确认开启；当前会话空输入、空附件/引用/命令/队列；空闲且可见；稳定 500ms | 请求、会话、完成轮次、上下文、模型版本仍匹配；得到一条合法候选 | Tab / Enter 只插入，不在同一按键发送 | 输入变化、菜单、组合输入、会话/上下文/模型变化、关闭、卸载、超时 |
| 输入续写 | 实际编辑后，光标同步至文本末尾；至少六个非空白字符；Host 已确认开启；纯文本、空闲、可见、无菜单；稳定 800ms | 原草稿版本、上下文、模型和选区仍有效；返回仅追加的文本；能定位到真实光标 | 仅 Tab 追加；Enter 仅发送原草稿 | 编辑、选区/焦点变化、组合输入、菜单、优化开始、模型变化、关闭、卸载、超时 |
| 草稿优化 | 用户点击按钮；有非空纯文本；无引用/命令/队列；空闲 | 生成后显示原文、优化结果和单独的待补充信息 | 确认替换时重新校验完整草稿版本、附件和上下文；一次公开输入 CAS 操作，不发送 | 用户取消、草稿/附件/上下文/模型变化、卸载、超时 |

请求已开始、模型已返回、结果被丢弃、结果已经显示、文本已采纳是不同状态。日志和测试不能把其中一个当作其他状态成功的证据。

## 本次定位到的问题

1. 原 Client 和 Host 都在三秒取消，真实日志曾在约 3013ms 结束。自动请求现在以 Host 十秒、Client 十一秒为上限；编辑和上下文变化依然立即取消。不会等到上限才显示已完成结果。
2. 模型请求成功返回后仍出现 `invalid-format`，原协议只接受 JSON 字符串。现在优先请求有命名字段的 JSON 对象，并兼容单字符串及单 `text` 字段；拒绝列表、多候选和未知对象，不截取第一条作为结果。
3. 编辑器会先发布内容版本，后同步浏览器光标。旧检查可能在中间状态耗尽当前编辑的唯一机会；现在先同步失效旧请求，再到下一动画帧确认光标并开始稳定窗口。IME 提交也走此路径。
4. 开关 UI 先乐观显示开启，Profile 写入可能稍后完成。现在“立即关闭”和“等待 Host 确认后开启请求”分开处理，避免向仍关闭的 Host 请求并消耗机会。
5. 组件切换/重建后，Host 曾只记得“请求过”，没有返回之前有效的结果。现在仅在内存中缓存最多 32 个会话的完成结果，重读前校验当前身份；不重新调用模型，失败不自动重试。
6. 旧日志无法区分正常编辑取消和误取消。续写现在记录固定的编辑门槛、显示状态和取消原因码；不记录草稿、候选、上下文或凭据。

## 验证层级

- 状态测试：超时、乱序/迟到响应、取消、重建缓存、Host 确认竞态、光标延迟、IME、菜单、键盘采纳、附件与上下文版本保护。
- 真实服务边界：Cordis 注入、Settings 描述默认值、Profile 升级及 Loader 启动。
- 真实浏览器、模拟模型：宽屏、390px 窄屏、深色、仅图标入口、390×500 长内容滚动和底部操作可达；截图在 `delivery/ai-assist-preview/`。
- 真实模型、真实应用：必须同时核对 `model-start`、成功结果、客户端显示，以及采纳后草稿变化；还需验证取消不覆盖后续编辑。当前窗口自动化的截图/定位通道故障，不能以模拟验证冒充这一级完成。

2026-10-25 用户重启后的真实运行日志已确认：17:54:17 建议同时出现 Host `ready` 和 `client-shown`；17:54:56 续写同时出现 Host `ready` 和 `client-result-shown`。用户随后确认两项均实际可见，Tab 采纳正常且没有发送消息。这完成了该会话的真实显示和采纳验收，不代表所有会话、加载时序和模型响应都已逐一验收。输入框“优化草稿”入口使用无默认背景、无边框的 `ghost` 按钮变体，保留项目通用悬停与键盘焦点反馈。

## 不同会话的差异

正常限制包括：新会话没有完成的上下文、输入中存在草稿/引用/附件、最后一轮被中断、模型未配置或不可用、继续编辑/移动光标，以及模型返回空内容或超过十秒预算。续写还要求实际编辑后的末尾光标和至少六个非空白字符。日志中既有约十秒的超时，也有随后约两秒的成功显示。

另有一处历史会话竞态已修复：会话服务先交付历史记录，再异步激活其现有 Agent；辅助请求曾在这两者之间立即判为不可用。`waitForInputAgent` 现在通过公开创建事件等待既有激活，关闭“查询—订阅”的竞态，并在取消/超时时释放监听；不会自行创建、恢复或启动 Agent，也不要求发送消息。三个辅助入口共用这一处理。只有模型选择变化、对话内容未变化的已有历史，也不再被误判为新内容；旧记录没有模型路由时采用既有默认模型。

新增回归覆盖了延迟激活的三种辅助请求、无关会话事件、监听注册竞态、超时/取消释放、模型选择后使用历史、旧记录默认模型。真实会话的具体失败仍应通过当前门槛及请求/返回日志判断，不应一概解释为模型性能。

## 日志解释

| 日志 | 含义 |
| --- | --- |
| `request` / `model-start` | 触发、上下文读取或模型调用开始，尚不表示显示成功 |
| `ready` | Host 有合法结果，还需检查 Client 显示 |
| `client-shown` / `client-result-shown` | 建议/续写通过当前客户端状态与显示门槛 |
| `client-result-unpositioned` | 有续写结果但没有可用的当前文本呈现表面，不能拦截 Tab 采纳隐藏内容 |
| `empty-or-invalid` / `invalid-format-*` | 模型无有效内容或返回结构不满足协议 |
| `client-cancel-*` | 取消原因：编辑、上下文、可用性、光标、优化开始、关闭、卸载或超时 |
| `cached-ready` | 取回仍有效的完成结果，没有新模型调用 |
| `already-attempted` | 当前上下文曾尝试但没有可恢复的有效完成结果，不自动重试 |

续写不保证对已经完整表达的句子强行补字。实际验收应使用明确未完成的草稿，例如“请帮我为这个功能补充”，并在等待期间保持光标在末尾；不要用“有请求日志”替代可见结果与采纳验收。

## 续写排版

原来的固定定位浮层从光标处另起一个窄文本列，既不能随正文向左换行，也不能撑高输入区，导致越界和工具栏重叠。现在在当前输入段落末尾使用独立的 CSS 生成内容：首行接在正文后，换行回到正文左边界，继承正文的字号和行高，由原输入区自适应高度与滚动容器承载。

样式属性加在 Desktop 自己的外层，不插入编辑器节点，不更改草稿模型。模型返回值作为经过转义的单个 CSS 字符串使用；双引号、反斜杠和换行保留为文本。采纳前，复制与可访问性文本框值仍只有原草稿。Tab 在可用的呈现表面与匹配的草稿版本下才采纳，采纳仍调用公开的输入 CAS 操作。

六种真实浏览器模拟案例验证了宽屏、窄屏、大字号、长英文串、多行和特殊字符，均无横向越界或工具栏遮挡，并验证采纳前内容隔离及 Tab 只插入不发送。完整 Desktop 检查通过 203 个文件、1807 项测试，11 项跳过。截图和浏览器验证日志保存在 `delivery/ai-assist-preview/`。
